The defect One line, in a function that already had everything it needed.

A parameter that was never referenced

def _body_heading_title(h4_inner: str, code: str) -> str:
    ...
    m = _HEAD_CODE_PREFIX_RE.match(s)   # positional. `code` unused.

The strip ran off a positional pattern built on grammar.CODE:

CODE = r"\d{1,4}-?[A-Z]{0,4}"   # a HYPHEN, never a SPACE

Two real families print the code with a space in the text layer. The match ended after the digits and the letters stayed in the title.

Why nothing caught it Two gates, both looking past the thing they exist to hold.

The register could not see a failing case

test_register_snapshot.py is what gates the pipeline on CI, because the corpora are gitignored and the lane suites skip there. It read the suite's output with one regex:

_FAIL = re.compile(r"\[ *FAIL \((\d+)\)\] +([a-z_]+)")

That matches [ FAIL (3)] section_carries_its_body — an invariant, which carries a count. It never matched [FAIL] <case_id>, which is pass/fail. Cases are this project's locking mechanism: every fix ships pinned by one in the same PR. So the mechanism protecting every fix already made was gated by nothing — and two cases were already failing when the round opened.

And a case scoped to the wrong document

Round 11's lock carried applies_to: "as amended up to 30.06.2021", matched as a substring of the filename. The acts lane holds two documents with that date:

The round-11 lock had been reporting a failure on a document it was never about. Every other scoped case was swept: two match multiple documents and both are deliberate, none matches zero.

The fix Already written, one file over.

Drive the strip from the code you were handed

discover._heading_from_words solves this exact disagreement, and its comment says why: the code arrives folded while the words carry the printed spelling. The same construction now backs _body_heading_title — but the longest match wins, and neither pattern could be dropped.

cands = [m for m in (_head_code_prefix_re(code).match(s) if code else None,
                     _HEAD_CODE_PREFIX_RE.match(s)) if m]
m = max(cands, key=lambda c: c.end())

Two measurements forced that shape, and both were found by re-converting and diffing — not by reasoning.

What it cost The first attempt shipped a regression. The diff caught it.

Two ways to get this wrong

The code-driven pattern alone strips too little

Where the body prints a suffix the TOC's code lacks — 15A. Title under code 15 — it matches the digits and leaves A. behind, reintroducing the very shape being removed. The positional pattern spans it.

The separator run swallowed the code's own terminator

Customs 193A prints 193. Appeals to Collector. The first attempt matched 3 + ". " + A and took the title's first letter with it:

193A  'Appeals to Collector (Appeals)'
   →  'ppeals to Collector (Appeals)'

discover._heading_from_words carries the same construction and a comment claiming its len(code)-1 bound makes this impossible. The bound limits how many separator runs there are, not how far one reaches, so it does not hold for a code whose letter suffix also begins the title word. That comment is still wrong in discover.py — same latent shape, not triggered there by this corpus, and logged rather than changed without a measurement to justify it.

The code token now has to end on a boundary, which makes that case fall through to positional — the right answer there.
