01The interpreter nothing agreed on

Four places in this repo name an interpreter. Three said 3.12. The one that actually ran the pipeline said 3.14.7, and no OCR wheel exists for it.

Before

.venv on Python 3.14.7, against pyproject.toml's requires-python = ">=3.12", CI's python-version: '3.12', and the container's own 3.12.

Every OCR import missing — not out of date, absent:

numpy ModuleNotFoundError onnxruntime ModuleNotFoundError rapidocr_onnxruntime ModuleNotFoundError cv2 · pyclipper · shapely ModuleNotFoundError

After

.venv on Python 3.12.13 — the version everything else already claimed. 58 packages.

Every OCR pin resolved unchanged on cp312. Nothing had to move, so no re-pin and no ocr_review.py run was owed:

numpy 2.5.1 onnxruntime 1.28.0 rapidocr_onnxruntime 1.2.3 opencv-python 5.0.0 · pyclipper 1.4.0 · shapely 2.1.2

The pins carried a note saying they were measured on Python 3.13. They are now measured on the 3.12 that CI and the container run, and the file says so.

03Phase 2 could not run — and one way it could have emptied a lane

Phase 2 is "re-convert every lane with --profile auto". Reading the converter, it could not do that, and the closer failure mode was worse than a missing flag.

Before · convert_all.py

The batch converter — the only practical way to reach 168 source files — hardcoded its child command. --profile appeared nowhere in the file; it existed only on convert.py, which converts one PDF.

argv = [sys.executable, "convert.py", LANE, str(pdf), "-o", str(dest)]

After

Threaded through convert() exactly the way --admit-below-floor already was, and refused up front for a lane whose pipeline cannot take it.

argv = [sys.executable, "convert.py", LANE, str(pdf), "-o", str(dest)] if profile != "lane": argv += ["--profile", profile]

What --profile auto on the ordinance lane would have done

Not "fail". This chain runs to completion, and every link already existed:

  1. 1The ordinance lane maps to fbr_ingest, whose run takes no profile parameter.
  2. 2convert.py exits 2 on each of the lane's 45 files: error: the ordinance pipeline takes no profile
  3. 3That reason is not an _is_env_failure — it names no missing module, so the guard that protects against exactly this does not fire.
  4. 4_quarantine moves each file's previous output out of output/. All 12 ordinance JSONs, gone from the corpus, on a flag typo.
  5. ✓Now cut at step 1. One check in main(), before any file is touched, asking the pipeline the same question convert.py asks. The run refuses; nothing is converted and nothing is moved.

Locked by tools/tests/test_convert_all_profile.py, which fails if either half is removed — verified by removing them. Its guard test fakes the source directory present, because without that it would pass on CI for the wrong reason: the corpus is gitignored there, so the earlier "no source directory" check would return 2 whether or not the guard exists.
