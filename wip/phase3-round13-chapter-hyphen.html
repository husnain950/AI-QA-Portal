The authority, and the two copies that drifted from it

# grammar.py — right, and asserts so in its own _demo
CHAPTER_RE = rf"^\s*\[?\s*{spaced('CHAPTER')}[\s\-]+({NUMERAL}) ..."

# builder.py — the parser's cut
_STRUCTURAL_RE = r"^(CHAPTER\s+[IVXLC0-9]+|PART\s+...)$"

# tools/suite/invariants/_common.py — the invariant that reports a missed cut
_STRUCT_LINE   = r"^(CHAPTER\s+[IVXLC0-9]+|PART\s+...)$"

So Chapter-II was not a boundary. Nine chapter headings per Sales Tax Act edition were swallowed into the preceding section's body — and no_structural_heading_in_body, whose entire job is to find a structural heading sitting in a body, reported zero, blind for the same reason.

Round 1 found the body scan, the tree and the invariant each reading one chapter numeral differently. Round 12 found two normalisers disagreeing about one code spelling. This is the third time, on the same shape.

Cross-references were never at risk: the pattern is whole-line anchored, so Chapter-V of this Act; has never matched and still does not.

Three things only running it found

The conservation audit read a canonicalisation as a loss. The first run came back 18/19, one edition at 99.975%, six missing words — every one the token Chapter. No text left the document: a boundary line is furniture, the tree holds it as a node, and the audit counts that node's code precisely so the words net out. They net out only where the source also prints the keyword in upper case. The Sales Tax Act prints Chapter-II; discover mints CHAPTER II; the multiset is case-sensitive. Folded, for four container keywords only — and the hole that leaves is named in the code rather than buried. Re-run: 19/19 at 100.000%.

One document loses 32 words, and it is the Phase 5 compilation. Customs Rules 2001 goes 74.101% → 74.087%. The tokens are four chapter captions cut out as boundaries into a tree that holds 41 of ~44 chapters and cannot express them. Inside a known 62,519-word deficit, on the one document whose containers are known to be inexpressible — but a real loss, and the second measurement arguing for the container-code guard.

One preamble was nothing but the leak. Eighteen editions ended their preamble …as follows:-\n4[Chapter-I\nPRELIMINARY — the chapter's own code and caption, emitted twice. On the 2014 edition the preamble was 24 characters and was only that, so the node is now absent. inv_preamble_present stays green by its documented fallback.

A fourth scanner that walks through a boundary

Three register hits were expected to close — the 32AA cluster. Its body is fixed. Its heading is not:

before  text     '6[32AA. ***]\nChapter-VII\nOFFENCES AND PENALTIES'
after   text     '6[32AA. ***]'
both    heading  '*** Chapter-VII OFFENCES AND PENALTIES 33. Offences and penalties'

_find_heading_split scans up to four lines ahead for a heading terminator. It stops at a grid table — its docstring argues a table "can never be part of a heading" and that this is "the same rule on the build side" — but not at a structural heading, which cannot be part of one either. So an omission with no terminator of its own borrows section 33's.

The obvious guard was measured, and it loses section 32AA outright: 127 leaves → 126. With no split the caller creates no entry at all. This needs an omission-aware fallback, not a guard.

So the register holds at 34, deliberately, with the class closed corpus-wide and the invariant that can see it shipping at 0 in the same PR — the same shape as round 12.

Locked Each verified by removing its fix, one at a time.

The last file is the one that would have caught this twelve rounds ago. The three modules stay independent implementations on purpose — an invariant that imports the parser's own regex checks nothing — but nothing compared them, and that is exactly how one separator came to have three spellings.

A docstring was corrected with it. The invariant's tariff-reference exception claimed "every genuine chapter boundary prints CHAPTER". The Sales Tax Act prints Chapter-II, so that was false — and the exception stays correct only because its split(" ") cannot split a hyphen. Widening it to match the pattern's own separator silences 171 of these 175 hits. Now asserted, not assumed.
