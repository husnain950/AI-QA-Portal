Front matter numbers its pages in roman. So a roman folio was never dropped as furniture, survived into body_refs, and everything before the first section's anchor becomes the preamble.

Round 13's shape exactly, and round 1's before it: two readers, one question, two answers.

The band could not be the test

footer_min_top is calibrated from body pages, and front matter is set to a different depth — the Customs 2008 folio prints at top 673.9 against a band starting at 702.5. So the test is what a folio is: roman, centred, alone on the last line of the page, below the midpoint.

Measured over the front matter of six editions: 65 roman-shaped lines, 64 of them folios running i…xxii on consecutive pages, and one a Sales Tax clause marker (iii) — correctly kept, because it is neither last nor in the bottom half.

Bounded at ccxcix and lowercase, for a reason worth writing down: mix is a valid roman numeral (MIX = 1009) and an ordinary English word, and an uppercase I is a drop cap. A plain [ivxlcdm]+ — which is what calibrate uses — eats all three. That looser test stays looser on purpose: it asks where is the band, where a false positive costs one sample; this one asks delete this line.

Cause 2 A contents page that measured zero contents rows.

A schedule row carries no code

The folio was only the last line of that page. The rows above it are still there. And detect_toc_pages is correct — the tail page simply is not part of what it counts:

pdf p21  lines=25 rows=13 ratio=0.52   contents
pdf p22  lines=24 rows=14 ratio=0.58   contents      detect_toc_pages = 22
pdf p23  lines= 6 rows= 0 ratio=0.00   contents TAIL, read as body

Zero rows on a page that is nothing but contents, because _is_toc_row reads a row as code, title, folio — and a schedule contents row has no code: THE FIRST SCHEDULE 213.

The pattern already existed. grammar.SCHEDULE_TOC_RE is the anchored, already-narrowed form; its own note records the wrapped citation THE FIFTH SCHEDULE TO THE ACT……… 45 that the unanchored version read as a schedule title, switching the parser into schedule mode mid-body and losing two chapters. Reused rather than rewritten — and it still rejects that line here.

Measured over both profiles and all 90 resolvable documents: 4 changed, 86 unchanged. The four are exactly the 2013–2016 editions.

The gate It would have reported zero on a document that still has the defect.

Removing the folio removed the only signal

Customs 2008 still carries four contents rows in its preamble. But the folio was the only thing the invariant could see there — so after the parser fix it would have passed, and this round would have closed the class on paper while one document silently kept it.

A third branch reads a schedule contents row straight out of the preamble text. It is deliberately looser than the parser's — it tolerates the SHCEUDLE typo — because it only reports; the parser's must not, because it cuts.

One limitation is pinned rather than hidden. (iv) alone on a line is indistinguishable from a folio in the JSON; the parser separates them by geometry and an invariant cannot see geometry. Measured at 9 roman-shaped lines over 1,292 preamble lines corpus-wide, every one a folio — so the check is worth more than the risk, and the test that says so is where that trade-off is written down.
