The defect An 18-rule chapter, pages 143–152. Not one rule bound.

150 ZQR is section 150ZQR

Sales Tax Rules 2006 carries a chapter on video-surveillance monitoring. Every rule in it became a heading-only leaf, and rule 150ZQP's body swallowed the lot. The reason is a single space: 

150 ZQR. Application.—The provisions of this Chapter shall apply
   ↑ _candidate_code requires the code contiguous → None
The guard “widen only if that changes”

A note that told us exactly what to check

_DOTSUFFIX_RE already reads a split suffix, but it is bracket-gated, and the bracket is load-bearing: a dot- or space-separated suffix only prints on an inserted section, which always carries its amendment bracket. The same shape unbracketed is a tariff row. Its comment ends: 

# ponytail: bracket-gated, so an UNBRACKETED dot-separated code is still missed.
# Measured over the corpus's 186,357 distinct body lines, all 146 unbracketed
# instances of the shape are tariff/schedule rows -- widen only if that changes.

So the first thing this round did was re-run that measurement, over 186,984 lines. It has changed. Two real families now print the shape with no bracket at all — the 150 ZQ* run, and 32 hyphenated Customs Act sections such as 196-A. Statement of case to Supreme Court….

The note was still right about the danger. Dropping the gate outright gains 392 lines, and they are precisely what it describes: 

1 ITEM NAME 7.5 1 9.23 132.23
10. PDA Delivery System
102 THE GAZETTE OF PAKISTAN, EXTRA.. JUNE 26, 2014[PART |
So the gate stays, and a second, narrower alternative is added beside it — not in place of it.

Three narrowings, each measured against the row it excludes

Together: 48 lines gained, 0 lost. Forty-seven are the two families; the forty-eighth is a TOC leader row minting the code 325AA, which no TOC entry carries, so it is indexed and never read.

Each narrowing has a case in builder._demo() that fails if it is removed — verified by removing them one at a time.

One hit became newly visible

section 150ZQZA: chapter caption in heading 'RESPONSIBILITIES OF THE VENDOR'

A false positive — and now that the rule binds, we can see why. The source prints 150 ZQZA. RESPONSIBILITIES OF THE VENDOR.–(1) Subject to these rules,: the section's own title is genuinely in capitals, and _CHAPTER_CAPTION_IN_HEADING matches any run of three-plus capitalised words.

Round 5 tests what the invariant means instead — does the caps run match a caption actually on a chapter node of this document? Measured over every current hit, that separates them cleanly: the three real leaks all match a chapter in their own tree, and this one does not.

Process Recorded because the next person will hit it too.

A stale __pycache__ nearly shipped a wrong number

The lock was verified by patching each narrowing out and re-importing. That left Python holding a compiled copy of the mutated module — so the pattern in memory was the lone-capital version this round explicitly rejects, while the source on disk was correct.

pytest caught it: _candidate_code("20 T. V. Sets Nos.") returned 20T instead of None. But the first re-conversion had already run against that bytecode, so its numbers could not be trusted. Everything was cleared, the compiled pattern asserted in a fresh process, and both lanes converted again.

The second run produced the identical register, 78 — the bogus 20T and 42G codes match no TOC entry, so they were indexed and never read.

Which is the same reasoning used to accept 325AA above. The re-run cost eighteen minutes and turned that reasoning into a fact.
