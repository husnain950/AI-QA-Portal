The premise Re-measured before touching anything, and it did not hold.

Not one of the 42 rewrites was TOC chrome

normalize_heading exists to strip table-of-contents debris that leaked into Act section headings — dot leaders, page numbers, gazette mastheads. The ledger estimated that most of its firings were now collateral. The corpus says all of them are: no page number stripped, no masthead, no Section Page No. column. Eleven parser rounds closed the entire reason the function exists, and nobody had re-measured it against its own premise.

[...] is not chrome. It is the pipeline's deliberate “text omitted by amendment” marker — emitted with its own omitted-bracket class in both builders, and preserved by name in the sanitizer allowlist as data rather than decoration. A dot-leader run and an omission marker are the same characters. That is the whole defect.

The fix The prototype passed. The function did not.

The marker had two attackers, not one

The deferred note named one — the dot-leader substitution. Guarding it took 42 rewrites to 24 and left every truncated case exactly as it was. The second attacker sits four lines below:

if had_leaders:
    text = _DOT_LEADERS_RE.sub(" ", text)          # attacker 1
...
    text = _TRAILING_TOC_PAGE_RE.sub("", text).strip(" .·•…")   # attacker 2

_TRAILING_TOC_PAGE_RE requires a digit, so it never matched — but the .strip() mops trailing dots unconditionally, and Directorate General of Valuation [... ends in three of them. That is what produced the bare [.

Both are now guarded on one rule: an unclosed [ means those dots are the marker.

_DOT_LEADERS_RE   = re.compile(r"(\[[^\]]*\]?)|(?:[.…·•]{2,}|…+)")
_LEADERS_PRESENT_RE = re.compile(r"(?:[.…·•]{2,}|…+)")   # the bare probe

text = _DOT_LEADERS_RE.sub(lambda m: m.group(1) or " ", text)
if text.rfind("[") <= text.rfind("]"):
    text = text.rstrip(" .·•…").rstrip(" .")

The optional closing bracket is what covers the truncated form. A second pattern keeps the had_leaders probe honest — probing with the guarded one would answer true for any heading containing a bracket.

Found by measuring the real function over the corpus. The prototype regex, tested in isolation on the same strings, passed.

The thing only running it found

Re-syncing the same database with the new parser is skipped 2, 0 rows changed — with --force too. create_version gates on source_hash, the JSON bytes, and a change in how those bytes are interpreted is invisible to it.

That gate is correct and was designed in deliberately. It simply does not model an API-side parse change, and both consequences are worth stating plainly:
